## Prácticas de Código Limpio y Principios SOLID

### Buenas practicas

- resuelven desafíos de escenarios comunes
- estándares comprobados y verificados
- brindan guías fáciles de aprender y comprender y fáciles de aplicar
- permiten tener una estructura similar para multiples proyectos

### Código limpio

buenas practicas del código

- código fácil de entender y analizar
- código fácil de mantener
- código fácil de actualizar
- código fácil de escalar

como lograrlo

- Mantener bajo acoplamiento
- Utilizar sintaxis simple y actual
- Evitar incorporar muchas librerías de terceros
- Distribución de responsabilidades
- Creación de componentes pequeños

SOLID nos ayuda a tener codigo limpio y buenas practicas

## Principios SOLID en Programación Orientada a Objetos

- S single responsibility principle : unica responsabilidad componente involucrados en el sistema
- O Open/close principle : estar abierto a extenciones cerrado a cambios
- L Liskov substitution principle: relacion entre tipos y subtipos dentro de un sistema
- Interface segregation principle: ayuda asignar responsabilidad especifica a cada una de las interfaces del sistema
- Dependency inversion principle: injectar dependencias para evitar acoplamiento en el codigo

### Caracteristicas de solid

- Orientada al paradigma de orientacion a objetos (POO)
- Se le atribuye a Robert C. Martin
- Diseño y refactirizacion de codigo
- se debe implementar desde el inicio del proyecto cuando se crean los componentes
